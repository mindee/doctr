Exporting results#

A Document can be exported to six formats. All of them present the content in the same reading order, which follows columns, places headers and footers, and adapts to right-to-left scripts.

Format

Method

Output

Best for

Plain text

render()

str

Search indexing, NLP, LLM prompts

JSON

export()

dict

Storing every word with its geometry

Markdown

export_as_markdown()

str

LLMs, RAG pipelines, readable documents

AsciiDoc

export_as_asciidoc()

str

Technical documentation toolchains

HTML

export_as_html()

str

Web display

hOCR (XML)

export_as_xml()

list[tuple[bytes, ElementTree]]

Searchable PDFs, OCR interoperability

The same methods exist on a single Page. The export_as() dispatcher selects the format by name, which is convenient when it comes from a configuration:

result.export_as("markdown")  # or "md"
result.export_as("asciidoc")  # or "adoc"
result.export_as("html")
result.export_as("text")  # or "txt", same as render()
result.export_as("json")  # or "dict", same as export()
result.export_as("xml")  # or "hocr", same as export_as_xml()

Plain text#

text = result.render()

Blocks are separated by a blank line and pages by three blank lines. Both separators are configurable, and page headers and footers can be left out:

text = result.render(page_break="\f", include_furniture=False)

Markdown, AsciiDoc and HTML#

markdown = result.export_as_markdown()
asciidoc = result.export_as_asciidoc()
html = result.export_as_html()

The structure of these exports depends on what the predictor detected:

  • Without layout analysis, blocks become paragraphs.

  • With layout analysis (detect_layout=True), the layout regions are used to render titles and section headers as headings, list items as lists, and to place the page furniture (headers, footers, footnotes).

  • With table recognition (detect_tables=True), tables are rendered as real tables.

Useful options:

escape (Markdown, AsciiDoc)

Escape the characters that carry a meaning in the markup (*, #, |…). Enabled by default.

include_furniture

Include page headers, page footers and footnotes. Enabled by default.

page_break

The separator inserted between pages: --- in Markdown, <<< in AsciiDoc, <hr> in HTML.

images

How figures are rendered, see Figures below.

hOCR#

hOCR is an open standard to store OCR results in XML. docTR produces one hOCR document per page, as raw bytes and as an xml.etree.ElementTree.ElementTree:

for page_idx, (xml_bytes, xml_tree) in enumerate(result.export_as_xml()):
    with open(f"page_{page_idx + 1}.hocr", "wb") as f:
        f.write(xml_bytes)

hOCR files are the input of tools such as hocr-tools or OCRmyPDF. The Export as PDF/A notebook shows how to turn docTR results into searchable PDFs.

Reading order#

Every export path shares the same linearization of the page, computed once and memoized. It:

  • follows the columns of multi-column layouts instead of reading straight across the page,

  • infers the reading direction from the recognized text (right-to-left for Arabic or Hebrew, for instance),

  • uses the layout regions, when available, to order blocks, headings, tables and figures and to place the page furniture.

Force the direction when automatic detection is not what you want:

result.export_as_markdown(direction="rtl")  # 'auto', 'ltr', 'rtl', 'ttb-rtl' or 'ttb-ltr'

To get the elements of a page (blocks, tables and optionally figures) in reading order, for your own exporter:

for item in result.pages[0].items_in_reading_order(include_figures=True):
    print(type(item).__name__, item.render()[:40])

The JSON export follows the reading order by default (export(reading_order=False) keeps the detection order). To sort the Document tree itself, build the predictor with keep_reading_order=True.

Figures#

When the layout model runs (detect_layout=True or detect_tables=True), the regions it labels as figures (pictures, charts…) take part in the reading order. The Markdown, AsciiDoc and HTML exports render them according to their images argument:

Mode

Rendering

"placeholder" (default)

A comment marks the figure: <!-- image --> (Markdown, HTML) or // image (AsciiDoc)

"none"

Figures are left out

"embedded"

Each figure is cropped and inlined as a base64 data URI: the export is self-contained

"referenced"

Each crop is written to a directory and linked by its relative path

 
from doctr.io import DocumentFile, FigureEncoder
from doctr.models import ocr_predictor

predictor = ocr_predictor(pretrained=True, detect_layout=True)
result = predictor(DocumentFile.from_pdf("report.pdf"))

# A self-contained Markdown file, figures included
markdown = result.export_as_markdown(images="embedded")

# A Markdown file linking to the crops written to `assets/`
markdown = result.export_as_markdown(images=FigureEncoder("referenced", image_dir="assets"))

FigureEncoder also sets the image format (png, jpg, webp), the quality of lossy formats, a padding around each crop, and a path_prefix when the export is not written next to the image directory. Crop file names contain the position and a hash of the figure (e.g. page1_figure2-3fa2b1c9.png), so several documents can share a directory.

Note

Once a figure carries its pixels ("embedded" and "referenced"), the text recognized inside it is left out of the export, since the image shows it, and its caption becomes the alternative text of the image. Plain text never contains figures, and hOCR positions them as ocr_photo areas.

From the command line#

The CLI exposes all these formats; the format is inferred from the extension of the output file:

doctr-cli --input_path report.pdf --detect_layout --output report.md --images referenced
